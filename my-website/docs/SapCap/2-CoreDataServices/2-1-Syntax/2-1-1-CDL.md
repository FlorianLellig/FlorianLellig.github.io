# 2.1.1 - Conceptual Definition Language (CDL)

Die Conceptual Definition Language ist ein wesentlicher Bestandteil der Core Data Services, der sich mit der Definition von Modellen beschäftigt.


:::note
**Bestandteile des Abschnittes**

- `namespace` zur Erstellung von Namensräumen
- `using` als Lösung zum Import
- `entity` zur Erstellung von Entitäten
- `Association to` und `Composition of`
:::

## 2.1.1.1 - Namensräume und Modularisierung

Namensräume verhindern Konflikte in komplexen Systemen und strukturieren das Projekt analog zu Java-Packages. Ein Namensraum wird mit dem Schlüsselwort `namespace` deklariert.

```sql
namespace sap.capire.bookshop;
```

Um bestehende Definitionen wiederzuverwenden, nutzt CDS die `using`-Direktive. Diese erlaubt es, Typen, Entitäten oder Aspekte aus anderen Dateien oder NPM-Modulen zu importieren.

```sql
using { managed, cuid, Country } from '@sap/cds/common';
```

:::tip
Das Modul @sap/cds/common ist hierbei von zentraler Bedeutung, da es Standard-Definitionen liefert, die die Interoperabilität zwischen verschiedenen CAP-Anwendungen sicherstellen. Der Compiler sucht diese Module in den node_modules-Ordnern des Projekts.
:::

## 2.1.1.2 - Datentypen in CDL


| CDS Typ | Beschreibung | ANSI SQL Entsprechung |
| :--- | :--- | :--- |
| `UUID` | Universell eindeutiger Identifikator (RFC 4122) | NVARCHAR(36) |
| `String(length)` | Zeichenkette mit definierter Länge (Standard: 255) | NVARCHAR |
| `Integer` | 32-Bit Ganzzahl | INTEGER |
| `Int64` | 64-Bit Ganzzahl für große Zahlenbereiche | BIGINT |
| `Decimal(p, s)` | Festkommazahl mit Präzision p und Skala s | DECIMAL |
| `Double` | Gleitkommazahl | DOUBLE |
| `Boolean` | Wahrheitswert (true, false, null) | BOOLEAN |
| `Date` | Datumsangabe (JJJJ-MM-TT) | DATE |
| `Timestamp` | Zeitstempel mit Mikrosekunden-Präzision | TIMESTAMP |
| `LargeString` | Große Textmengen (CLOB) | NCLOB |
| `LargeBinary` | Binärdaten (BLOB) | BLOB |

## 2.1.1.3 - Domänenmodellierung: Entitäten und Strukturen

### Definition von Entitäten

Eine Enbtität ist eine zentrale Einheit der Datenmodellierung. Sie wird durch das Schlüsselwort `entity` eingeleitet und enthält eine Menge von Elementen, von denen mindestens eines als Primärschlüssel (`key`) makiert sein muss

```sql
entity Books {
  key ID    : UUID;
  title     : String(111);
  stock     : Integer;
  price     : Decimal(9,2);
}
```

:::warning
Bei der Verwendung von `UUID` als technischen Schlüssel muss diese mittels `using` importiert werden.
:::

### Strukturierende Elemente in Entitäten

CDS erlaubt die Definition von Strukturen innerhalb von Entitäten, was die Lesbarkeit verbessert und logische Gruppierungen ermöglicht.

```sql
entity Books {
  key ID    : UUID;
  title     : String(111);
  stock     : Integer;
  price     : Decimal(9,2);
}
```

### Virtuelle Elemente in Entitäten

Elemente können mit `virtual` makiert werden, um CDS mitzuteilen, dass diese Felder lediglich zur Laufzeit existieren und nicht in der Datenbank aufzufinden sind. Die zugehörigen Werte werden meist im Backend berechnet und für temporäre UI-Zwecke genutzt. 

```sql
entity Bookshop {
  key ID                      : UUID;
  shopname                    : String(111);
  shopowner                   : String(111);
  virtual distanceToWalldorf  : Integer;      #Virtueller Datensatz
}
```

## 2.1.1.4 - Beziehungsgeflechte: Assoziationen und Kompositionen

Die Modellierung von Bezeihungen ist ein essenzieller Bestandteil von CDS. Man unterscheidet hierbei zwischen Assoziationen und Kompositionen.

### Assoziationen 

Assoziationen beschreiben Beziehungen zwischen unabhängigen Entitäten. Ein Autor kann exisiteren, ohne das er Bücher geschrieben hat und auch ein Buch bleibt prinzipiell ein Buch, wenn der Datensatz des Autors gelöscht wurde.
Man unterscheidet zwischen:
- **To-One Assoziation:** Verknüft einen Datensatz mit genau einem Zielobjekt.
- **To-Many Assoziation:** Verknüpft ein Objekt mit einer Menge von Zielobjekten. Hierbei muss eine `on`-Bedingung angegeben werden, die meist auf einen Rückverweis-Element im Zielobjekt zeigt.

```sql 
entity Books {
  author : Association to Authors;
}

entity Authors {
  books : Association to many Books on books.author = $self;
}
```

:::info
Das Schlüsselwort `$self` ist hier eine Art Platzhalter für die aktuelle Entität. Um diese Assoziation in der Datenbank zu realisieren passiert alles automatisch (im Hintergrund).
:::

### Kompositionen

Kompositionen modellieren eine "Teil-Von" Beziehung, bei denen das Kond-Objekt in einer existenziellen Abhängigkeit von dem Eltern-Objekt steht.

```sql
entity Orders {
  key ID : UUID;
  items : Composition of many OrderItems on items.parent = $self; 
  # Ein OrderItem kann nur existieren, wenn auch eine Order existiert
}
```

:::info
Kompositionen lösen im Java-Backend automatisch spezielle Automatismen aus, die bereits implementiert sind:
- **Cascaded Delete:** Wenn eine Bestellung gelöscht wird, werden automatisch alle zugehörigen OrderItems aus der Datenbank gelöscht
- **Deep Insert/Update:** Über eine einzige OData-Anfrage kann eine gesamte Struktur konsistent angelegt oder geändert werden.
:::

## 2.1.1.5 - Standards und Wiederverwendbarkeiten

### Der `@sap/cds/common` Standard

- `cuid`: Ermöglicht das Nutzenvon UUID
- `managed`: Ergänzt die Felder `createdAt`, `createdBy`, `modifiedAt` und `modifiedBy`

### Wiederverwendbare Typen

`@sap/cds/common` stellt ebenfalls Typen für globale Stammdaten zur Verfügung, die als sog. _Managed Associations_ zu Standard-Codelisten führen.
- `Country`: Verweist auf ISO-Ländercodes.
- `Currency`: Unterstützt Währungscodes nach ISO Standard.
- `Language`: Verarbeitet Sprachcodes und Locales
